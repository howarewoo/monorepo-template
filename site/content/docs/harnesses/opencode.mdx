---
title: opencode
description: Per-call model routing through opencode's subagent primitive.
---

opencode lets woostack select a model when starting each worker. Woostack resolves the task's
`fast`, `standard`, or `deep` tier and passes the corresponding model. Independent tasks are
submitted together. Woostack limits concurrency only when the installed runtime cannot run
workers in parallel.

Woostack passes the working directory when the runtime supports it. The task prompt always names
the exact worktree, the separate checkout assigned to that task.

No automatic fallback managed by opencode is documented for provider usage limits. If the runtime
cannot accept the selected model, the worker uses the session model and woostack reports that
limitation.

For detection, worker behavior, per-skill instructions, and fallback rules, read the
[canonical opencode reference](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/opencode.md).
