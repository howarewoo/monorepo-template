---
title: Cursor / Composer
description: Parallel dispatch with session-model tier collapse.
---

Cursor's Composer runtime can run independent workers in parallel. Woostack cannot select a model
or reasoning effort separately for each worker, so every task uses the session model. To change
the model used for a requested tier, change the session model before the run. Woostack reports
when a requested tier cannot be routed separately.

Cursor also cannot set a separate working directory for each worker. The task prompt names the
expected worktree, the separate checkout assigned to that task, and the worker must use it before
writing.

If the provider's usage limit is exhausted, the worker returns an error. No automatic fallback
managed by Cursor is documented.

For detection, worker behavior, per-skill instructions, and fallback rules, read the
[canonical Cursor reference](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/cursor.md).
