# woostack-review troubleshooting

## Troubleshooting

- **Missing artifacts** in cloud mode — verify the `detect` job uploaded `review-artifacts`.
- **Empty adjudicator output** — inspect `$OUTDIR/raw_findings.json`. If empty, no angle wrote findings; check each `findings.<angle>.json`.
- **Sub-agents posting prematurely** — re-read the Stage 3 brief; workers must write JSON only.
- **`gh api ... /reviews` returns HTTP 422 "Line could not be resolved"** — re-read the exact PR head and inspect the finalizer's `inline` classification. `intersect-findings.sh` resolves locations; `build-review-payload.py` preserves accepted unanchored findings as general comments. Never drop a finding or invent a replacement anchor to make posting succeed.
- **Stale findings from a prior run** — use the fresh per-run `OUTDIR` from `resolve-outdir.sh` and canonical prefetch. A contaminated local tree blocks; never clear another in-flight review to make it reusable.
- **`detect-angles.sh` crashes outside GitHub Actions** — fixed: the script now emits `angles=` / `chunks_json=` lines to stdout and writes `$OUTDIR/angles.json` + `$OUTDIR/chunks-matrix.json` when `$GITHUB_OUTPUT` is unset. Inspect those files when running locally.
- **Sub-agent writes findings to the wrong path** — caused by host workspace drift (the sub-agent's CWD differs from the orchestrator's). Export `OUTDIR` to every sub-agent — see Stage 1 in the root skill.
- **The adjudicator output was rejected** — inspect the first failed boundary. `verify-receipts.sh` requires the exact adjudicator receipt and local controller-bound identity/digests; `intersect-findings.sh` rejects malformed output or findings outside changed paths. An unresolved inline location alone is preserved, not rejected.
- **Caller-side PR resolution blocked by host sandbox** — resolve the user-supplied exact PR number with a separate canonical read and export `PR_NUMBER`. Never infer the target from the current branch.
- **`prefetch.sh` skipped with "bot already commented and trigger is not explicit" on a local run** — fixed: that re-run guard now only applies inside GitHub Actions (`GITHUB_ACTIONS=true`). Local `/woostack-review` invocations are explicit by definition and no longer trip the gate.
- **GitHub API rejects `REQUEST_CHANGES` / `APPROVE` on a self-authored PR** — fixed in `_orchestrator-header.md`: immediately before posting, the payload builder reads the immutable numeric ID of both `gh api user` and the canonical PR author at the reviewed head. It uses `REQUEST_CHANGES` / `APPROVE` only when both reads are complete and the IDs differ; the same or an unproved actor posts `COMMENT` while preserving the computed STATUS_LINE. Logins, host profiles, sessions, credential labels, and token-store names never satisfy this proof.
- **A worker died or left malformed output** — follow the controller header's **Worker completion** protocol. The bounded runner retains retry/crash accounting in `swarm-metrics.json`; missing receipts or malformed output after recovery block posting, not a degraded approval.
- **Bad JSON escapes** — serialize from structured data and parse the saved artifact before the receipt. Merge rejects malformed JSON; it never deletes escape characters to salvage a finding.
- **Large diff under-reviewed / a changed file never got findings** — `prefetch.sh` caps the diff at `WOO_REVIEW_DIFF_CAP_BYTES` (default 300KB). The cap is section-aware (issue #150): it keeps whole `diff --git` sections ranked by review value (sections that add lines first; pure file deletions, lockfiles, and generated files last) until the budget is hit, never splitting a section. When sections are dropped it emits a `::warning::` and lists the dropped paths in `$OUTDIR/diff-dropped.txt`. If a real file was dropped, raise the cap (`WOO_REVIEW_DIFF_CAP_BYTES=600000`) or narrow scope with `review.ignore` so low-value paths are excluded before the cap applies.
